# Ғылым — помощник экспертного совета

Бот: https://t.me/QuryltaiScience_bot
Версия 1.0: приём предложений в личных сообщениях, документы, статусы, администратор.

## Запуск на Render

1. Создайте отдельный **приватный** репозиторий GitHub `quryltai-science-bot`.
2. Распакуйте архив. Загрузите содержимое папки проекта в корень репозитория, включая `app.py` и `render.yaml`. Токен не добавляйте в репозиторий.
3. В Render выберите **New → Blueprint**, подключите этот репозиторий. Перед созданием проверьте стоимость: конфигурация использует платный web service Starter и постоянный диск 1 GB. Ресурсы ещё не созданы этим архивом.
4. Введите `TELEGRAM_BOT_TOKEN` — токен именно @QuryltaiScience_bot из BotFather.
5. Для `ADMIN_IDS` на первом запуске введите `0`, если не знаете свой числовой Telegram ID. Значение `0` никому не предоставит права. Секрет `WEBHOOK_SECRET` генерируется Blueprint автоматически.
6. После успешного запуска откройте бота, нажмите Start и отправьте `/id`.
7. В Render → Environment замените `ADMIN_IDS=0` на полученный числовой ID. При нескольких администраторах укажите ID через запятую. Сохраните с перезапуском.
8. Отправьте `/start`, затем протестируйте: `/new` → текст → файл как документ → `/done` → `/list` → `/view 1` (используйте фактический номер).
9. Для изменения статуса: `/status 1 review`. Автор получит уведомление.

Webhook регистрируется автоматически при старте. Render предоставляет HTTPS и переменную `RENDER_EXTERNAL_URL`. Не запускайте одновременно другую программу с токеном этого же бота.

### Если создавать Web Service вручную

- Runtime: Python 3.
- Build Command: `python -m compileall -q app.py`
- Start Command: `python app.py`
- Health Check Path: `/health`
- Постоянный диск: mount path `/var/data`, 1 GB. Создайте его **до приёма реальных заявок**.
- `DB_PATH=/var/data/bot.sqlite3`
- `TELEGRAM_BOT_TOKEN`: секрет из BotFather.
- `WEBHOOK_SECRET`: случайный секрет из 32–256 латинских букв, цифр, `_` и `-`. Получить локально: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
- `ADMIN_IDS`: сначала `0`, затем свой ID через `/id`.

Нельзя хранить рабочую базу на обычной временной файловой системе Render: при перезапуске/развёртывании такие данные теряются. Не запускайте несколько экземпляров приложения на одном диске.

## Что умеет версия

- `/new`: создание черновика; несколько сообщений до 20 000 символов суммарно.
- До 10 файлов как «Документ» на черновик. Фото можно отправить как файл.
- `/done`: регистрация; администраторы получают номер предложения.
- `/cancel`: удаление черновика вместе с метаданными вложений.
- `/my`: последние 30 собственных предложений и статусы.
- `/id`: свой Telegram ID. Он не даёт прав автоматически.
- `/list [страница]`: список по 20 записей, только администратору.
- `/view НОМЕР`: текст и повторная отправка вложений администратору.
- `/status НОМЕР new|review|done`: Получено / На рассмотрении / Рассмотрено.
- `/summary`: количество предложений по статусам. Это НЕ ИИ-анализ.
- `/about`: краткое описание работы совета.

## Хранение и ограничения

База SQLite сохраняет Telegram ID, отображаемое имя, тексты, статусы, даты UTC, Telegram file_id и названия вложений. **Файлы не скачиваются на сервер:** хранятся ссылки-идентификаторы Telegram, по которым бот повторно отправляет документы. Это не независимый архив файлов; для длительного архивирования требуется отдельное хранилище.

Бот не читает содержимое PDF/Word, не генерирует ИИ-справки, не планирует заседания и напоминания, не подключён к сайту. Это следующие этапы после проверки приёма заявок. Все сообщения в группах игнорируются; отключать Privacy Mode не требуется.

Поступившие материалы доступны только их автору в виде собственного списка статусов и администраторам через команды. Отдельной проверки членства эксперта пока нет: любой пользователь, открывший бота, может подать предложение. Перед широкой публикацией нужны ограничения нагрузки и согласованный порядок работы с персональными данными.

Повторная доставка одного update не создаёт повторную заявку. Ответы ставятся в постоянную очередь вместе с изменением базы. Временные ошибки Telegram повторяются с задержкой; постоянные ошибки помечаются `failed` в outbox и отражаются в журнале без текста материалов и токенов. После сбоя между отправкой и удалением очереди возможен повтор исходящего сообщения, но не повтор заявки. Заблокировавшему бота пользователю уведомления не доставляются.

Периодически проверяйте failed-записи и свободное место. Для согласованной резервной копии SQLite используйте sqlite3.Connection.backup(), а не копирование одного файла при работающем WAL. Храните резервные копии в контролируемом месте. Сроки хранения и удаление зарегистрированных заявок в интерфейсе пока не реализованы.

## Проверка локально

Требуется Python 3.11+; внешних пакетов нет.

`python -m unittest -v`

Тесты проверяют повторные обновления, сохранность после повторной инициализации, вложения, удаление черновиков, права администратора, изоляцию пользователей, запрет групп и проверку webhook-секрета. Для тестов токен не требуется; сообщений в Telegram они не отправляют.
